# Журнал решений

Краткие архитектурные записи: контекст, решение, последствия. Все решения приняты 2026-10-28.

## ADR-1. Next.js (App Router) вместо React + Vite + Express

- **Дата:** 2026-10-28
- **Контекст.** Исходное задание рекомендует React + Vite + Express. ТЗ допускает другой стек при обосновании. Нужны UI и REST API в одном origin и один процесс, который можно перезапускать.
- **Решение.** Один проект на Next.js 16 (App Router): UI — страница с Client Components, API — Route Handlers в `app/api/**/route.ts` (`runtime = 'nodejs'`, `dynamic = 'force-dynamic'`). Логика живёт вне фреймворка в `src/server/`, route-файлы тонкие.
- **Последствия.** Нет proxy и CORS, один `build` и один процесс. Цена: Next.js тяжелее Vite + Express; жизненным циклом сервера управляет `next start`, а не наш код; у Route Handlers нет цепочки middleware, поэтому валидацию и ошибки делают `parseJson`, `parseQuery` и `withErrors`. Смена стека согласована с заказчиком 2026-10-28 (подтверждение проверяющего — вне этого репозитория).

## ADR-2. better-sqlite3 без ORM

- **Дата:** 2026-10-28
- **Контекст.** Источник истины — один файл SQLite. Нужны синхронные транзакции `BEGIN IMMEDIATE`, partial unique index и точный контроль над SQL.
- **Решение.** `better-sqlite3` (в списке `serverExternalPackages` Next.js, не бандлится), только prepared statements, без ORM. Репозитории содержат весь SQL. `node:sqlite` остаётся запасным вариантом под тем же интерфейсом репозитория, но не используется: он experimental.
- **Последствия.** Нативная сборка на целевой машине (проверено: Node 22.23.1, macOS arm64). Тесты используют тот же драйвер, включая `worker_threads` с независимыми соединениями.

## ADR-3. Имена сотрудников не уникальны

- **Дата:** 2026-10-28
- **Контекст.** Исходное задание допускает дубликаты при условии документирования. Уникальный индекс по имени запретил бы нанять двух тёзок.
- **Решение.** Уникальности нет ни в БД, ни в API. Если имя повторяется, UI добавляет короткий суффикс id (`Alice Smith · #a1b2`) в списках и выпадающих меню; при совпадении первых символов id суффикс удлиняется. Сортировка по имени без учёта регистра ASCII, затем по `id`.
- **Последствия.** Ответы API не меняются; различимость обеспечивает только UI. Сервер не может «защитить» от случайного повторного создания сотрудника — это осознанный выбор.

## ADR-4. Время в БД — целые миллисекунды Unix epoch (UTC)

- **Дата:** 2026-10-28
- **Контекст.** Нужны точная арифметика пересечений, индексы по времени и отсутствие разбора строк.
- **Решение.** `INTEGER` в `STRICT`-таблицах; в API — ISO 8601 с `Z`. Единственная формула вклада `overlapMs` живёт в `src/server/domain/time.ts`. Сервер не знает часовых поясов: принимает только instants со смещением, а календарные даты в instants переводит браузер (локальная полночь; конечная дата включительна).
- **Последствия.** Нет дрейфа при переносе сервера между поясами; сутки на переходе на летнее/зимнее время бывают 23 и 25 часов (покрыто тестами при `TZ=Europe/Chisinau`). Дата без смещения отклоняется как неоднозначная.

## ADR-5. Откат системных часов при остановке

- **Дата:** 2026-10-28
- **Контекст.** Если часы сервера ушли назад (NTP), `now < startedAt`, и `CHECK (ended_at >= started_at)` сделал бы остановку невозможной.
- **Решение.** Остановка — один `UPDATE … SET ended_at = max(?, started_at) WHERE id = ? AND ended_at IS NULL RETURNING`. Если значение было поднято до `startedAt`, в лог пишется предупреждение (только id таймера).
- **Последствия.** Инвариант `endedAt >= startedAt` не нарушается, таймер всегда можно остановить; длительность такой записи — 0. Само расхождение часов не исправляется.

## ADR-6. Блокировка БД — 503 DB_BUSY

- **Дата:** 2026-10-28
- **Контекст.** При конкуренции соединение может ждать блокировку дольше `busy_timeout` (5 с).
- **Решение.** `SQLITE_BUSY` и `SQLITE_LOCKED` превращаются в `503 DB_BUSY` с заголовком `Retry-After: 1`, а не в 500. Нарушения ограничений SQLite не должны доходить до клиента как 500: известные превращаются в бизнес-коды 409 в сервисе.
- **Последствия.** Клиент может безопасно повторить запрос. Покрыто тестом на настоящую блокировку второго соединения.

## ADR-7. Двойная защита инварианта «один активный таймер»

- **Дата:** 2026-10-28
- **Контекст.** ТЗ (BR-1, BR-4) требует и проверки в сервисе, и partial unique index.
- **Решение.** Сервис выполняет проверку и `INSERT` в одной транзакции `BEGIN IMMEDIATE`; индекс остаётся последней линией защиты.
- **Последствия.** Каждый слой по отдельности держит инвариант, поэтому мутация «убрать только индекс» роняет лишь тесты уровня БД, а S7 и S12 остаются зелёными (см. README, «Bugs Found and Fixed»). Это расходится с формулировкой ТЗ 11.5 и зафиксировано как факт, а не скрыто.

## ADR-8. Миграции как строки в TypeScript, серверный код с `.ts`-импортами

- **Дата:** 2026-10-28
- **Контекст.** Файлы `.sql` могут не попасть в сборку Next.js; тестам на `worker_threads` нужно загружать серверный код без сборщика.
- **Решение.** Миграции лежат в `src/server/db/migrations.ts` и применяются по `PRAGMA user_version`. Код в `src/server` и `src/shared` использует относительные импорты с расширением `.ts` и только «стираемый» синтаксис TypeScript (`erasableSyntaxOnly`), поэтому Node 22 загружает его напрямую.
- **Последствия.** Миграции нельзя править «задним числом»: только добавлять новые версии. Для запуска `scripts/seed.ts` и воркеров нужен Node ≥ 22 с поддержкой type stripping (проверено на 22.23.1).
